= CloudWatch Insights for JSON logs
// Not sure how placement will affect publishing to Confluence
:toc: left

This page is a collection of pre-built CloudWatch Insight filters designed to quickly enable searching of logs. To lower
the bar, it is desirable to have a number of pre-defined queries in place to help with quick searching and debugging.
The easiest way to guarantee that the pre-defined queries are available to everyone is to put them under code control
like everything else. On this page we present how to run these queries manually and how to put them under IaC control.

[NOTE]
To change the number of returned results increase the `limit` number.

=== Filter by log level

.DEBUG
[%collapsible]
====
[source, bash]
----
fields @timestamp, @message, @logStream, @log
| filter level = 'DEBUG'
| sort @timestamp desc
| limit 20
----
====

.INFO
[%collapsible]
====
[source, bash]
----
fields @timestamp, @message, @logStream, @log
| filter level = 'INFO'
| sort @timestamp desc
| limit 20
----
====

.WARN
[%collapsible]
====
[source, bash]
----
fields @timestamp, @message, @logStream, @log
| filter level = 'WARN'
| sort @timestamp desc
| limit 20
----
====

.ERROR
[%collapsible]
====
[source, bash]
----
fields @timestamp, @message, @logStream, @log
| filter functionVersion = '259'
| sort @timestamp desc
| limit 20
----
====

=== Filter by function version

[%collapsible%open]
====
[source, bash]
----
fields @timestamp, @message, @logStream, @log
| filter functionVersion = '259'
| sort @timestamp desc
| limit 20
----
====

=== Filter by request id

[%collapsible%open]
====
[source, bash]
----
fields @timestamp, @message, @logStream, @log
| filter function_request_id = 'd61a89e7-3eba-4a37-892a-c944de787789'
| sort @timestamp desc
| limit 20
----
====

=== Filter by cold start

[%collapsible%open]
====
[source, bash]
----
fields @timestamp, @message, @logStream, @log
| filter coldStart = 'true'
| sort @timestamp desc
| limit 20
----
====

=== Filter by service

[%collapsible%open]
====
[source, bash]
----
fields @timestamp, @message, @logStream, @log
| filter service = 'ltr-service-dev'
| sort @timestamp desc
| limit 20
----
====

=== Filter by message like

[%collapsible%open]
====
[source, bash]
----
fields @timestamp, @message, @logStream, @log
| filter @message like /clientId/
| sort @timestamp desc
| limit 20
----
====

=== Filter by message contains

[%collapsible%open]
====
[source, bash]
----
fields @timestamp, @message, @logStream, @log
| filter strcontains(@message, "clientId")
| sort @timestamp desc
| limit 20
----
====

== Queries under IaC control
It is also possible to pre-define queries using IaC to make execution a breeze. Please see the following for how to use
your flavor of IaC to pre-define the CloudWatch Insight queries.

[CAUTION]
Please be aware that to be able to save a Log Insight Query using IaC the executing role
will require the `logs:PutQueryDefinition` IAM permission.

To create a query in CloudFormation/Serverless it will look as follows ...

* link:../../../engineering/ops/infrastructure-as-code/aws/aws-cf-create-cloudwatch-insight-query.adoc[CloudFormation: (AWS) Create CloudWatch Insight Query]
* link:../../../engineering/ops/infrastructure-as-code/serverless/sls-aws-create-cloudwatch-insight-query.adoc[Serverless: (AWS) Create CloudWatch Insight Query]
* link:../../../engineering/ops/infrastructure-as-code/terraform/tf-aws-create-cloudwatch-insight-query.adoc[Terraform: (AWS) Create CloudWatch Insight Query]
