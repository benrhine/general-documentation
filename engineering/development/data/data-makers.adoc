Makers are the required tooling for adding data generation into your application. As discussed in link:data-generation.adoc[Data: Generation]
makers are a tool to enable generating test data in a variety of ways with the goals of speeding up development and
improving testing of an application.

== What is a maker?

What a maker is has already been discussed in link:data-generation.adoc[Data: Generation] but a quick recap ...

A maker is an additional coding structure (i.e. internal tool) that is used to generate dynamic test data at test time to
improve test coverage and diminish the amount of time required to write tests.

== When to write a maker?

Makers should be written at the same time a domain object is written. For example ...

* A new Automobile object class is added to the code
** Then an AutomobileMaker class should be added

        return  makeBaseData(false, OffsetDateTime.now(), null, UUID.randomUUID(), UUID.randomUUID(),
                5L, UUID.randomUUID(), UUID.randomUUID(), UUID.randomUUID(), DataType.TEST_PURGEABLE, true);

                                        final OffsetDateTime updateDate, final UUID createUser, final UUID updateUser,

                .tenantId(tenantId)

Within the `ExampleMaker` there are many variations of data creation that can be selected depending on the tests required.
First note that all the fields use random to generate strings and other data that will always be unique per run to guarantee
that each unique data set is being saved. Additionally, note that we can also use the maker to generate lists of this object
or use the maker to create JSON versions of the object.

Having the ability to quickly create unique data for tests saves a huge amount of time and effort for developers as when
they add to a given test set they no longer have to image the test data, they can just generate it.
