This is an attempt to document all the errors that were overcome during the initial development period and their solutions for future reference to ensure quick resolution of any future issues. Additionally, it is intended to educate about issues that may be seen during deployments and how to remediate them.

Gotchas

When running updates with serverless each node in the serverless.yml file must be unique

resources:                              # Specify all resources below
  Resources:                            # Resource list
    receivingDevTopic:					# NODE 1
      Type: AWS::SNS::Topic
      Properties:
        TopicName: ${self:custom.queueName}-topic-dev
    receivingTestTopic:					# NODE 2
      Type: AWS::SNS::Topic
      Condition: CreateQueueNpResources
      Properties:
        TopicName: ${self:custom.queueName}-topic-test

each of the above will create its own topic. If you change the node name and the topic name, IT WILL NOT CREATE A NEW ITEM as the node has already been registered and will be treated as an update. What this means is if you change the above as follows …​

resources:                              # Specify all resources below
  Resources:                            # Resource list
    receivingDevTopicNew:				# NODE 1
      Type: AWS::SNS::Topic
      Properties:
        TopicName: ${self:custom.queueName}-topic-dev-new
    receivingTestTopic:					# NODE 2
      Type: AWS::SNS::Topic
      Condition: CreateQueueNpResources
      Properties:
        TopicName: ${self:custom.queueName}-topic-test

instead of having 3 topics now receivingDevTopic will be replaced by receivingDevTopicNew (i.e. it is overwritten).

Caution
 While the above is unclear until you have seen it, this may be an issue when generating roles. If you want to create a new role that is unique this may require some extra thought.

Role DELETE_FAILED

This is commonly seen when running the remove jobs. This happens as policies fail to detach from the roles.

Actual Error

  DELETE_COMPLETE - AWS::IAM::Role - lambdaServiceRole
  DELETE_FAILED - AWS::CloudFormation::Stack - ltr-service-resources-dev
Environment: linux, node 18.16.0, framework 3.32.2, plugin 6.2.3, SDK 4.3.2
Credentials: Local, environment variables
Docs:        docs.serverless.com
Support:     forum.serverless.com
Bugs:        github.com/serverless/serverless/issues
Error:
DELETE_FAILED: codebuildServiceRole (AWS::IAM::Role)
Cannot delete entity, must detach all policies first. (Service: AmazonIdentityManagement; Status Code: 409; Error Code: DeleteConflict; Request ID: fb400bdc-d49b-4426-bb28-6fc8a26f6d49; Proxy: null)
View the full error: https://us-west-2.console.aws.amazon.com/cloudformation/home?region=us-west-2#/stack/detail?stackId=ltr-service-resources-dev
[Container] 2023/06/20 16:03:58 Command did not exit successfully serverless remove --config serverless-resources.yml --verbose exit status 1
[Container] 2023/06/20 16:03:58 Phase complete: BUILD State: FAILED

Solution

  • Navigate to IAM

  • Select Roles from the left hand panel

    • Search for sls (all generated roles will contain this)

  • Select the role that didn’t delete correctly

  • View Permissions

  • Select all policies

  • Remove

  • Navigate back to CodeBuild

  • Select and Re-run YOUR-SHORT-APP-NAME-remove-resources job (Click Start Build)

The * -remove- * job should now complete successfully. Once the job has completed everything is cleaned up and you can now re-deploy the resources from scratch.

Unable to update Service Role in CodeBuild with error "The policy was not attached to role"

This error may occur after executing any *-resources-remove job. This happens as the roles that are configured for CodeBuild by the resource deploy have been removed and when they are regenerated they do not correctly re-attach to previous policies unfortunately. What this means is any job configured with these roles will need to be updated (probably deleted and recreated) in CodeBuild, same goes for any configured pipelines. To remove the policies to allow for recreation follow the steps below…​

Caution
 Be very careful when doing this. DO NOT DELETE ANY POLICIES THAT ARE "YOUR-APP- * -RESOURCES*

Solution

  • Navigate to IAM

  • Select policies

  • Search for the app short name (in this case ?)

  • Select each NON-RESOURCE policy and delete it.

With the policies removed it should now be possible to re-create the items in CodeBuild and to re-assemble the pipeline.

Solution?

  • check if any bad stacks relating to your build are stuck on aws here

  • if so remove them

  • check role permissions. I saw this when I had removed the s3 permissions from my lambda role. You may need to add the following

- PolicyName: ${self:custom.appShortName}-s3-policy
  PolicyDocument:
    Version: '2012-10-17'
    Statement:
      - Effect: Allow
        Action:
          - s3:GetObject
          - s3:GetObjectVersion

          - arn:aws:s3:::${self:custom.deployBucketName}/*

Solution?

This is most likely happening due to customDomain.domainName not being set correctly.

custom:
    ...
  domains: # For each deployment stage
    dev: # dev stage
      domainName: ${self:custom.appShortName}-${self:provider.stage}.brr-np.company.com
      certificateName: ${self:custom.appShortName}-${self:provider.stage}.brr-np.company.com
    ...
    prod: # token-req.brr.company.com
      domainName: ${self:custom.appShortName}.brr.company.com
      certificateName: ${self:custom.appShortName}.brr.company.com
  customDomain: # Get value from "domains" section using stage that is being deployed to create url in Rout 53
    domainName: ${self:custom.domains.${self:provider.stage}.domainName}
    endpointType: REGIONAL                              # Must be set or will fail to find cert
    apiType: http                                       # Must be set otherwise defaults to REST
    certificateName: ${self:custom.domains.${self:provider.stage}.certificateName}
    # Enable plugin to create an A Alias and AAAA Alias records in Route53
    # mapping the domainName to the generated distribution domain name.
    createRoute53Record: true
    # Enable plugin to autorun create_domain/delete_domain as part of sls deploy/remove
    autoDomain: true

plugins:                                                # Specify any additional plugins for serverless - be aware that these can increase cold start time
  - serverless-domain-manager
